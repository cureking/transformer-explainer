# 中文术语表与翻译规范

> 本文件是全站中文文案的唯一基准。所有译名必须以此为准；如需偏离，先改本文件再改代码。
> 参考依据：中文 NLP / 大模型社区通用译法、教材（《动手学深度学习》《深度学习》花书）与主流厂商中文文档。

## 1. 五条硬规则

1. **首次出现格式**：`中文（English）`，同一页面之后只写中文。例如「词元（token）」「自注意力（self-attention）」。
   例外：README、页面标题等独立上下文各自视为"首次"。
2. **中英文之间加一个半角空格**：`Transformer 块`、`GPT-2 模型`、`logits 向量`。中文与数字之间同样加空格：`12 个头`、`768 维`。
3. **图示窄标签压到 2–4 字**：用「图示短译名」列，不要用全称。例如注意力矩阵旁的 `Key` 译为「键」而非「键向量」。
4. **公式、代码、符号一律不译**：KaTeX 里的 `\text{logit}`、`Bias_1`、`Logits_1`、`\in`、`\infty`，代码块里的标识符，全部保持原样。只翻译公式**周围**的说明文字。
5. **标点用中文全角**：，。：；？！（）「」；不用英文逗号句号。括号内是英文时仍用半角括号。

## 2. 固定保留英文（不译名单）

这些词在中文 ML 社区已作为通用术语使用，强行翻译反而不专业：

`Transformer`、`GPT-2`、`Softmax`、`GeLU`、`Dropout`、`logits`、`Top-k`、`Top-p`、`MLP`（首次「多层感知机（MLP）」后可简称 MLP）、`Q/K/V`（与「查询/键/值」并用）、`BPE`、`ONNX`、`Svelte`、`D3.js`、`KaTeX`、`GitHub`、`Hugging Face`

人名（作者、致谢名单）、论文标题、库名、URL、arXiv/GitHub 链接：一律不译。

## 5. 长文与教学卡片的行文规范

- 语气：面向零基础读者的科普语气，简洁、准确，不用「我们大家」「众所周知」这类空话。
- 一段一意，长句拆短；避免英文式长定语（"这是一个用来……的模型"→ 拆成两句）。
- 缩写与符号保持原样，如 `x₁`、`d_model`、`W^Q`。
- 图注格式：`图 1. …`；编号与正文引用保持一致（`图 3`）。
- 章节标题层级原样保留（h1/h2/h3 不变），只译文字。
- 「Attention is All You Need」保留英文原名，首次可括注《注意力就是你所需要的一切》。
- 作者名单、致谢、GitHub 链接、论文引用（BibTeX）保持原样，只译括注性说明。

## 6. 质量红线（评审会逐条检查）

1. `token` 不得出现「令牌」；`logits` 不得出现「逻辑值」；`embedding` 不得出现「内嵌/嵌入式」。
2. 同一术语全站只能有一种译法（用 `grep` 自查）。
3. 公式、`<code>`、属性值（`id=`、`class=`、`href=`、`triggeredBy=`）**绝对不能改**——只能改人眼可见文本。
4. Svelte 语法（`{#if}`、`{#each}`、`{变量}`）不得破坏；HTML 标签必须闭合。
5. 中英文间空格、中文全角标点必须统一。
